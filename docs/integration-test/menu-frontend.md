## 5. 테스트 상태 및 우선순위 정의

| 상태        | 의미 / 갱신 조건                                                                   |
| ----------- | ---------------------------------------------------------------------------------- |
| NOT RUN     | 이번 통합 테스트 미실행. 선행 근거가 있어도 초기값은 유지                          |
| IN PROGRESS | 실행 중이며 필수 조건 확인이 남음                                                  |
| PASS        | 필수 조건 충족, 대상 버전·실제 결과·증거 존재. 재사용 부분도 차이 확인과 근거 필요 |
| FAIL        | 기대 결과 미충족. 필수 실패를 부분 성공으로 숨기지 않음                            |
| BLOCKED     | 환경·반영·담당 합의 등 선행 조건 미충족. 해소 담당/필요 판단 기록                  |
| RETEST      | 수정/재배포 후 재검증 필요. Fix PR·신규 이미지 연결                                |
| SKIPPED     | 제외 사유·영향·승인자/승인 근거가 있는 제외. 미확인·시간 부족을 PASS로 바꾸지 않음 |

- **P0 필수:** 정상 E2E, 인증·보안, 데이터 정합성, 담당 배포·복구·관측성의 필요 조건. 미해결 필수 결함이 있으면 완료하지 않는다.
- **P1 권장/선택:** F-08의 폭넓은 화면·조작 경계, 추가 단말 등. 필수 항목을 우선하며 제외 시 SKIPPED 승인 근거가 필요하다.
- P0에 해당하는 중대한 UI·인증 결함은 F-08이 P1이라는 이유로 미루지 않는다.
- 고부하·모든 장애 조합·Pod 분산의 반복 실측은 담당자의 기존 결과를 우선한다. 추가 실행은 합의한 필요 범위에 한정한다. 필수 조건이 남은 그룹은 PASS로 만들지 않는다.

## 6. 개인 통합 테스트 시나리오

각 그룹의 실제 결과·증거와 결함·재검증은 초기 미기록이다. 실행 후 9절 RUN/결함 기록을 연결한다.
API 예시의 ID는 전용 테스트 데이터로 바꾼다. 내부 API는 허용된 검증 경로에서만 호출하며 Frontend에서 직접 호출하지 않는다.

### 결함 관리

이번Smoke의 문제는 #414 관리 문서에 먼저 취합한다. 신규 결함은 **BUG-001부터 순차 발급**하며 이번에는 확정된 신규 제품 결함이 없어 미발급이다. P0 발견 시 영향 테스트를 중단하고, 일반 결함은 독립적인 시험을 계속한다.

발견 내용은 관리 문서에 먼저 취합한다. 동일 원인·담당·수정 범위의 일반 결함은 한 수정 Issue로 통합할 수 있고 독립적 결함은 분리한다. 중대한 보안·데이터 정합성·핵심 기능 차단은 즉시 별도 Issue로 추적하고 우선 수정한다. 기존 Issue가 추적하는 선행 조건 미충족은 중복 등록하지 않는다.

정식 처리 흐름은 **Issue→Fix PR→리뷰·병합→dev 재배포→재검증→문서 갱신**이다. 이번 RUN에는 신규 제품 결함이 없어 BUG ID를 발급하지 않았으며 이번 문서 확정 작업에서도 신규 Issue/수정PR 생성이나 제품 수정은 하지 않는다.
이 계획 문서에서 앱을 수정하지 않는다. 실패 증거를 성공 증거로 덮어쓰지 않는다.

이에 OBS-02는 **담당자 보고로 계획된 P-04 시험에 따른 교체로 설명된 관찰**로 정정한다. 최초 원인 미확정 관찰과 실제 Pod/이벤트 시각은 보존한다.
당시 조회한 #404 파일/댓글에는 상세 보고가 미반영이고P-04 NOT RUN이었다. **RUN-02 추가 대조:** 최신파일c98b760에는P-04 PASS·15:08전환/15:13복원·같은시간교체2회가명시되어문서갱신대기는해소되었다. 기존관찰/담당자보고/최신공동문서의확인시점을구분한다.
이 정정은 P-04/CT-04 또는 개인 그룹의 PASS를 새로 부여하지 않는다. 신규 결함0·기존13/8/2 집계를 유지한다.
Control Plane 메모리 부족 OBS-01은 독립적인 원인 미확정 운영 관찰로 유지하며 Payment 시험과의 인과관계를 단정하지 않는다.

동일 원인·담당·수정 범위의 결함은 한 Issue로 통합할 수 있고, 서비스·책임·원인이 다른 독립적 결함은 분리한다. 현 단계에서는 PRE-01/02를 기존 Issue로 추적하고 OBS의 원인을 확인한 후 분리/통합을 판단한다.

신규 결함 발생 시 다음 양식으로 기록한다. 현재는 실제 BUG 번호를 발급할 결함이 없다.

기존 보호 파일597개의 해시는 유지했다. 다른7개 worktree의 미커밋 상태도 같았다. 다만 실행 중 다른 작업 경로2개의 HEAD 진행이 관찰돼 되돌리거나 수정하지 않았다. 이RUN은 해당 경로에 쓰기 명령을 실행하지 않았다.
초기 로컬 리스너45개 중7개(프로세스8936/26112)가 종료 시 관찰되지 않았다. 원인은 미확정이며 이RUN에서 해당 프로세스를 종료하거나 재기동하지 않았다.
이번에 종료한 로컬 입력창/브라우저는 이RUN에서 새로 만든 것뿐이다. 따라서 기존 리스너 전부가 계속 유지됐다고 주장하지 않는다.
