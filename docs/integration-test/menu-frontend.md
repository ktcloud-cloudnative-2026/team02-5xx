- 영업/접수·PAYMENT_MOCK_RESULT·TTL·부하·Pod삭제·롤링·장애·이벤트 재전송은 영향·실행자·시간·복원값을 사전 합의한다. 변경 전 실제 값을 확인한다.
- 종료 후 전용 데이터·확보/환불 상태를 확인하고 공유 설정을 합의한 이전 상태로 복원한다. 단, 영업·접수는 Order 담당자가 전체 통합 테스트 종료 후 복원할 예정이므로 개인 RUN마다 끄지 않는다. 메뉴HIDDEN 등 정리는 담당 합의에 따르며 이력/재고 물리 삭제 금지.
- 공통 클러스터·DB·스토리지 변경은 담당자에게 요청한다. Inventory 내부·PostgreSQL·Redis 운영 책임을 임의로 인수하지 않는다.
- prod 환경 준비·배포 구현은 이 계획의 작업 범위가 아니다. prod 쓰기·설정 변경·장애 주입 금지. 최종 읽기 검증의 범위/담당/승인 없으면 미확인으로 남기며 준비 작업을 임의로 인수하지 않는다.

| RUN | 데이터 별명/비민감ID | 생성자/용도 | 공유 설정 변경 전→후(비밀값 제외) | 합의 근거/시간 | 복원 결과/시각 |
| --- | -------------------- | ----------- | --------------------------------- | -------------- | -------------- |
| —   | —                    | —           | —                                 | 미합의         | —              |

증거는 상태·시각·HTTP code/errorCode·비민감ID·마스킹한 화면/로그로 최소화한다.
Authorization·Refresh Cookie·Secret·비밀번호·개인정보·요청/응답 전문은 저장하지 않는다. HAR/화면/로그 첨부 전 마스킹을 확인한다.

## 9. 결함 및 재검증 기록

### 실행 결과 — 실행 후 추적

각 그룹 결과란에서 해당 RUN을 연결한다. 지금은 미실행이므로 실측 성공 행을 만들지 않는다.

| RUN / 개인ID / CT | 일시(KST)·환경 기록 | 실제 이미지/Git SHA | 실행 절차/실제 결과·HTTP·상태 | 판정    | 검증 근거/재사용 원본 | 결함Issue / Fix PR | 재배포 버전·재검증RUN |
| ----------------- | ------------------- | ------------------- | ----------------------------- | ------- | --------------------- | ------------------ | --------------------- |
| 미발급            | —                   | —                   | 미실행                        | NOT RUN | —                     | —                  | —                     |

### 결함 관리

**발견→별도 GitHub Issue→Fix PR→리뷰·병합→dev 재배포→재검증→이 문서 갱신**.
이 계획 문서에서 앱을 수정하지 않는다. 실패 증거를 성공 증거로 덮어쓰지 않는다.

| 결함Issue | 개인ID/CT·재현RUN | 우선순위/영향/기대와 차이 | 임시 조치/담당 합의 | Fix PR·수정SHA | dev반영 시각/이미지 | 재검증RUN/결과 | 남은 문제 |
| --------- | ----------------- | ------------------------- | ------------------- | -------------- | ------------------- | -------------- | --------- |
| 미발급    | —                 | —                         | —                   | —              | —                   | —              | —         |

중대한 인증 누출·중복 결제·재고/환불 불일치는 담당자에게 즉시 공유하고 영향을 받는 시험을 중단한다.
BLOCKED는 제품 결함과 구분해 필요 조건/확인처를 남긴다. SKIPPED는 제외 승인 근거를 남긴다.
