## API·화면 동작

- OR-08은 `/api/v1/admin/orders`, OR-09는 `/api/v1/admin/orders/{orderId}`의 같은 출처 GET이다. 기본 page=0·size=20, 크기 선택 20/50/100, 서버 최신순을 유지한다.
- KST 날짜는 양끝 포함 최대 31일이다. 기간 기준 모드는 기간·정확한 주문번호·상태·수동 확인을 AND로 검색한다. **주문번호 전체 기간 모드는 from/to를 키 자체부터 생략**한다. 빈 날짜 파라미터를 전송하지 않는다. `manualReviewRequired`는 true일 때만 전송한다.
- 목록은 목록 DTO 필드만 사용한다. 상세 사유·결제 ID·환불/복원 기록은 OR-09에서만 읽는다. 고객 이름·연락처·이미지는 생성하지 않는다. 미발급 주문번호는 내부 ID로 구분한다.
- 상세에 상품·옵션·수량·기본 단가·라인 금액·총액, 사용자/주문/결제 ID, 주문·결제·완료·취소·취소 요청 시각, 취소/실패 사유, 환불·재고 복원 시각, 후속 처리 시도 횟수와 수동 확인 사유를 표시한다. 생략된 시각은 기록 없음으로, 환불·복원 시각 누락은 미완료 또는 대상 아님으로 표시한다.
- 취소 후속 처리 `manualReviewRequired=true`와 `FAILED`의 `*_REFUND_NEEDED`는 별도 경고다. 실패 환불 필요를 수동 확인 필터에 임의 포함하지 않는다.
- URL hash에 적용한 필터·page·선택한 orderId를 보존한다. 상세 닫기·Escape·브라우저 뒤로가기는 목록 필터와 포커스로 복귀한다. draft 입력은 검색 제출 전 서버 조회를 바꾸지 않는다.
- API 봉투·상태·ID·시각·수량·금액·페이징·목록/상세 구조를 검증한다. 404 ORDER_NOT_FOUND, 비활성 API/일반 404 NOT_FOUND, 400, 401, 403, 네트워크·비정상 JSON·서버 오류를 구분한다. 자동 재시도하지 않고 명시적으로 재조회한다.
- 독립 요청 세대로 이전 검색/상세·닫힌 패널·이전 mount 응답을 무효화한다. 401/403은 목록·상세 데이터를 함께 비우고 진행 중 다른 조회도 무효화한다.

## 보안·향후 재사용

고객 `src/main.jsx`와 `App.jsx`는 관리자 화면을 import하지 않는다. 관리자 미리보기 진입점은 `tests/admin-orders-entry.jsx`이며 제품 번들에 관리자 UI·fixture 데이터가 들어가지 않는 검사를 추가했다. 요청은 Accept만 지정하고 X-User-Id·X-User-Role·가상 Bearer를 생성하지 않는다.

컴포넌트는 `api`를 주입받고 `createAdminOrderApi`는 `request`를 주입받는다. 실제 Auth/Gateway 준비 후 검증된 세션의 request에 연결할 수 있다. 그 준비가 이번에 완료된 것으로 표시하지 않는다. Order의 기본 `ORDER_ADMIN_ENABLED=false`를 유지하며 공유 dev/prod의 관리자 API를 켜지 않았다.
