# #201 비회원 장바구니 정책·UX 보완

## 사용자 확정 정책

`peak-order.cart.v1`은 계정별 서버 장바구니가 아닌 **현재 브라우저의 장바구니**다. 비회원·로그인 고객·STORE_ADMIN 모두 담기·보기·수량 변경·삭제를 사용할 수 있다. 이 데이터가 주문 권한을 부여하지 않는다. 장바구니 주문과 상세 즉시 주문·결제는 검증된 CUSTOMER와 사용자 식별자가 있어야 실행한다. STORE_ADMIN은 두 주문 경로 모두 차단한다.

- 비회원 담기는 로그인 모달을 열지 않는다. HTTP 검증을 마친 뒤 한 번 저장하고 장바구니 오버레이와 담기 결과를 표시한다. 검증 대기 중에는 ‘메뉴 확인 중…’을 표시하고 중복 요청을 받지 않는다. 성공 후에는 오버레이가 닫힐 때까지 추가 담기를 받지 않아 같은 클릭이 두 번 저장되지 않는다.
- 오버레이 아래 상세를 유지한다. 닫기·ESC·뒤로가기로 돌아오면 옵션·수량·검색·카테고리·정렬·탐색 상태를 유지한다. 브라우저 장바구니 deep link와 새로고침도 로그인 없이 사용한다.
- 주문 시 비회원이면 그 위치에서 로그인 모달을 겹쳐 띄운다. 취소하면 원래 장바구니/상세를 그대로 유지하고 대기 주문을 폐기한다. 나중 로그인으로 취소한 주문을 재생하지 않는다.
- 로그인 또는 세션 복원이 검증된 CUSTOMER로 완료되고 메뉴 검증도 준비되면 대기 주문을 정확히 한 번 재개한다. 상세 버튼은 **이 메뉴만 바로 주문**이며 현재 메뉴·옵션·수량만 사용한다. 기존 장바구니를 합치거나 수정하지 않는다.
- 장바구니는 로그아웃·계정 전환에도 유지된다. 이전 세션에서 대기 중이던 담기/주문과 진행 중 Checkout의 늦은 응답은 무효화한다. 새 CUSTOMER가 명시적으로 시도한 주문까지 영구 차단하지 않는다. 계정별 장바구니 이관·서버 저장 기능을 새로 구현하지 않았다.

## 구현 경계

`session.js`의 `planCartIntent`는 add/view를 공개 동작으로 분류하고 order/login만 인증 계획을 만든다. 기존 `canUseCustomerFeatures`는 CUSTOMER 주문 경계에 사용한다. 인증 Store·토큰·Refresh 구현 자체는 변경하지 않는다.

App은 검증 대기 동작을 ID와 참조로 추적하고, 소비하기 전에 실제 활성 요청인지 확인한다. Store의 인증 무효화/사용자·역할 변경 알림에서 대기 참조를 동기적으로 취소한다. UI Logout 외 Store Logout·계정 전환도 이전 동작을 재생하지 않는다. 컴포넌트 정리·메뉴 HTTP의 AbortSignal과 이전 응답 무효화는 기존 구현을 재사용한다.

기존 `readPendingCart`·`validateCartCatalog`·최신 상세 캐시 우선순위·대기 선택 메뉴 재검증을 유지한다. 메뉴 HTTP가 실패하면 저장소를 덮어쓰지 않고 금액과 조작을 검증 준비 전까지 보류한다. 새 가격·상태를 검증한 후에만 담기/수량 변경/주문을 실행한다. 확정된 판매 불가 항목 처리 정책과 저장 구조는 변경하지 않는다.

Checkout HTTP adapter·백엔드 계약·Order 20개 항목 제한·POST 자동 무재시도는 유지한다. 결과 불명은 OR-04 GET으로 확인한 CREATED에만 사용자 클릭으로 같은 orderId의 OR-02 POST 복구를 허용한다. 서버의 `order-{orderId}` 키를 사용하며 프런트 키·자동 반복·새 임시 주문은 없다. 장바구니 주문 성공에만 주문 당시 수량을 한 번 차감하고 나머지는 보존한다. 즉시 주문/실패/결과 불명에서는 장바구니를 수정하지 않으며, 조회 또는 같은 주문 복구 후 성공도 같은 후처리 경로를 사용한다. 테스트용 Mock adapter와 실제 HTTP adapter의 경계·제품 번들 제외 검사도 유지한다.

## 회귀 검증 기준

기존 Node 167건·Chromium 75건을 기준으로 한다. 인증 실패·CUSTOMER 역할 검사·키보드/모달·지연 응답·가격/판매 상태·실패/결과 불명·성공 후 수량 차감 검사를 유지한다. 과거 ‘비회원 담기/조회 시 로그인’, ‘STORE_ADMIN 장바구니 금지’ 같은 기대만 새 정책으로 바꾼다. 제거된 기능이나 정책에 맞지 않는 과거 기대를 통과시키려고 제품을 되돌리지 않는다.

추가 `guest-cart-browser.mjs`는 실제 App/Auth Store/Menu/Checkout HTTP 클라이언트와 loopback 계약 서버를 사용한다. 비회원 CRUD/오버레이/중복 클릭/선택 보존/deep link/재로딩/로그인 취소·복원/계정 전환/지연 응답·실패 후 재시도/즉시 주문 불변을 검증한다. 실제 dev Auth·Order·Cooking 서버나 Gateway 인증 전달 완료를 뜻하지 않는다.

수정 후보의 최종 검증: Node 168 PASS(기존 167 + 정책 검사 1), Chromium 91 PASS(기존 75개 시나리오를 정책에 맞춰 유지·재검증 + 새 비회원 장바구니 16). Vite build·변경 파일 Prettier·패치 공백 검사를 통과했다. 실패·결과 불명·정확히 한 번 수량 차감·HTTP/Mock 제품 번들 경계 검사는 그대로 통과했다.
