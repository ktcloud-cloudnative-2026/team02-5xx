### BUG-001 모달 포커스

기존 코드는 네이티브 dialog에만 포커스 경계를 맡겨 중첩 로그인 안내의 Tab 경계에서
BODY로 포커스가 빠지는 보고를 막지 못했습니다.
`dialogFocus.js`는 열린 dialog 순서를 문서별로 관리하고 최상위 dialog의
첫 요소 Shift+Tab/마지막 요소 Tab에만 기본 동작을 취소해 반대 경계로 이동합니다.
비활성·숨김·inert·음수 tabindex는 제외합니다. 내부 Tab과 브라우저 단축키는 가로채지 않습니다.
키보드 핸들러는 dialog에만 연결하고 전역 리스너를 추가하지 않았습니다.
열기·닫기는 네이티브 dialog, Escape는 최상위 cancel만 처리합니다.
기존 포커스·스크롤 잠금 복원을 공유하며 상세의 옵션·수량 state는 변경하지 않았습니다.

신규 자동 검사 5건은 실제 production handler를 DOM 모의 객체로 실행합니다.
양방향 순환, 내부 이동 유지, 하위 모달 무시, Escape 한 단계 종료,
이전 포커스/스크롤 복원·재열기, 제외 요소와 BODY 복구, 열기 실패를 검사합니다.
브라우저 네이티브 Tab/cancel 이벤트 발생 자체를 검증한 결과는 아닙니다.

### BUG-002 Vite fixture HMR

기존 `{ middlewareMode: true, hmr: false, ws: false }` 설정에서도
`transformIndexHtml`은 `/@vite/client`를 삽입합니다. 이 사실을 자동 검사로 재현했습니다.
WebSocket 서버를 끄고 클라이언트를 남긴 fixture 구조가 연결 오류와 일치합니다.
당시 브라우저의 WebSocket 핸드셰이크 원본을 재관찰한 것은 아닙니다.

fixture만 Vite `build(write: false)`의 메모리 JS/CSS를 제공하도록 변경했습니다.
`dist/` 기록·개발 HMR·React Refresh 클라이언트 없이 테스트 세션 주입을 유지합니다.
애플리케이션 의존성 버전·장바구니 로직·일반 dev 설정은 변경하지 않았습니다.

| 환경                   | 실제 HTTP/산출물 검사                                                    | 브라우저 Console                            |
| ---------------------- | ------------------------------------------------------------------------ | ------------------------------------------- |
| 기존 fixture 설정 재현 | HMR off에도 HTML에 `/@vite/client` 삽입 확인                             | Work 보고에서 연결 오류                     |
| 수정 fixture           | HTML/JS/CSS 200, `/@vite/client` 404, HMR 클라이언트·실패 로그 코드 없음 | Work 재검증: 최초 로드/새로고침 오류·경고 0 |
| 일반 Vite dev          | HTML에 `/@vite/client` 포함, client 200                                  | 실제 WebSocket 연결 성공은 미검증           |
| production preview     | HTML/JS 200, 제품 번들에 Vite client·실패 로그·테스트 세션 컨트롤 없음   | 실제 React 런타임 실행은 미검증             |

환경 구분 자동 검사 3건 통과, preview는 빌드 후 별도 HTTP 검사로 확인했습니다.
따라서 BUG-002를 장바구니/React 런타임 결함으로 판정하지 않습니다.

1. `npm.cmd run test:ui`를 재실행하고 **새로 출력된 주소**를 별도 테스트 탭에서 엽니다.

2. Escape 한 번은 로그인만 닫고 담기 버튼으로 복귀해야 합니다.
   세트·수량 2·18,000원과 상세 스크롤 유지 → 다시 열기/닫기 → Escape로 상세 종료.
   원래 메뉴 카드 포커스와 본문 스크롤 복원을 확인합니다.
3. 테스트 세션 주입 후 기존 추가·합치기·변경·삭제·99 상한·새로고침 흐름을 재실행합니다.
   대기 동작 자동 재개로 중첩 모달이 함께 제거돼도 스크롤 잠금이 남지 않아야 합니다.
4. fixture Console에 Vite WebSocket 연결 오류가 없는지 확인합니다.
   일반 dev/production preview와 비교하고, React 렌더 오류가 있다면 별도로 기록합니다.
5. 저장소 이상값/접근 예외는 별도 임시 브라우저 프로필·테스트 origin에서만 검사합니다.
   Work 도구가 주입을 제한하면 차단으로 기록하며 사용자의 기존 저장소는 변경하지 않습니다.

위 항목 1~4의 핵심 흐름은 최신 Work 보고에서 재검증 통과했습니다.
저장소 예외 등 제외된 범위는 계속 미검증으로 구분합니다.

## 로컬 실행

Node 24/npm 11에서 저장소 루트 기준:

```powershell
cd C:\M\Peak_Order\services\web-frontend
npm.cmd ci
npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

일반 앱은 <http://127.0.0.1:5173>에서 확인합니다. 기본 세션은 비회원이며
URL·localStorage·요청 헤더로 로그인 상태를 만들 수 없습니다.
브라우저 테스트용 별도 탭을 사용하고 작업 후 서버를 Ctrl+C로 종료합니다.

다른 PowerShell에서 다음 명령을 실행합니다.

```powershell
cd C:\M\Peak_Order\services\web-frontend
npm.cmd run test:ui
```

출력된 `http://127.0.0.1:<임의 포트>`를 엽니다. 이 페이지에만 테스트 세션 버튼이
있습니다. 토큰·계정을 사용하지 않으며 실제 인증 성공을 검증하지 않습니다.
새로고침 복원은 서버를 종료하지 않고 같은 주소에서 검사합니다.
서버를 재시작해 포트가 바뀌면 localStorage origin도 달라집니다.
네이티브 dialog가 열린 동안 하단 테스트 버튼도 비활성이므로 먼저 모달을 닫고
세션을 주입합니다. 대기 동작 재개는 모달을 열기 전 전용 예약 버튼을 사용합니다.
